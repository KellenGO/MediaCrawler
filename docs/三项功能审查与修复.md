# 三项功能审查与修复（2026-09-14）

本轮针对本地收藏夹、跨平台收藏持久化、无窗口启动进行修复，保留现有 UI 和接口结构；没有新增依赖、数据库表迁移或发布 Release。没有使用真实账号进行同步，所有写入测试使用临时数据库。

## 修复的问题

- 收藏列表此前由多个组件分别缓存，操作后容易出现状态不一致。改为共享查询缓存，并在写入成功后刷新。
- 备注保存失败时保留编辑内容，不再把失败的写入显示成成功。
- 收藏导入加入事务：结构错误时整体回滚；非法条目和容量限制按实际数量反馈；重复的内联收藏夹名称复用同一个收藏夹。旧数据迁移有跳过项时不会直接标记迁移完成。
- 单平台同步、失败或取消时，保留已保存的其他平台及历史内容；数据库读写失败会显示提示。同步任务的错误输出持续读取，避免子进程日志塞满管道后卡住。
- 收藏持久化保留互动数据的“近似值”等元信息，兼容已有 JSON 格式。
- 同步仍由用户主动触发，前端请求每平台最多 100 条；补充小红书、抖音分页测试，不将 100 条解释为平台保证可用的风控上限。
- 批量加入收藏夹成功后清除勾选，失败则保留选择。
- 托盘退出先通知后端正常结束，让清理和数据库写入有机会完成；超时才强制结束。搜索、登录、收藏同步的工作进程也使用隐藏窗口方式启动。
- 打包实测发现阻塞式读取控制管道会卡住 NumPy 的原生模块加载，改用 Windows 管道状态检查。普通后端和托盘控制后端均纳入 EXE 冒烟检查。
- 打包检查拒绝把顶层用户 data / .cache 目录装入发布包；恢复此前被删除的有效前端测试，并避免一次性编辑脚本在 pytest 收集时执行。

## 仍需明确的边界

- 尚未实测四个平台的真实账号同步，无法承诺每个平台一定返回 100 条；当前不是全量同步。
- 本地收藏仍沿用现有 500 条上限。
- 跨平台收藏是本机的一份归档。虽然存储层有 account_key 参数，当前任务管理器没有接入真实账号身份隔离；换账号同步可能合并到同一份本机归档，不应宣传为多账号隔离。
- 同步合并保留历史条目，不自动镜像删除平台上已取消收藏的内容。
- 系统托盘菜单的真实鼠标操作和 Windows 窗口显示情况仍需桌面人工验收；EXE 测试验证的是进程行为及无窗口编译配置。
- 测试构建位于 `build/review-dist/MediaCrawler`，不是已发布的更新；已有发布产物未替换。
