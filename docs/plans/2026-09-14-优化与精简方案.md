### 执行时踩到、值得写进 wiki 的坑

1. **`tools/file_header_manager.py` 不是死代码** —— 它被 `.pre-commit-config.yaml` 调用。判死代码要连配置文件一起 grep。
2. **mixin 必须排在抽象基类前面**：`class X(ReusableHttpClientMixin, AbstractApiClient)`。
   反过来写会让 `update_cookies` 解析到 `AbstractApiClient` 的 `@abstractmethod`，
   实例化直接 `TypeError`（`base/base_platform_client.py` 的 docstring 里已注明）。
3. **import 搬家会让测试的 `monkeypatch.setattr` 静默失效**：`make_async_client` 移到
   `base.base_platform_client` 后，原先 patch 各平台 client 模块的测试就打在空气上，
   表现为"真发请求 → tenacity 重试失败"。patch 目标必须跟着代码走。
4. **pytest 每次要换全新的 basetemp 子目录**：复用目录会触发沙箱的 safe-delete 批量保护，
   报成 116 个 setup ERROR 的**假回归**。
5. **Bash 工具双引号里不要出现反引号**：bash 会当命令替换执行、静默吃掉内容（踩了两次）。
6. **前端 `lib/` 之间 import 必须带 `.js` 后缀**：`tsc` 不报错，只有 `run-compiled-tests.mjs` 会暴露。

### 1.3 三个必须先看的硬问题

1. 🔴 **`proxy/` 773 行是死代码** —— `config.ENABLE_IP_PROXY = False`（无 env 读取），且 `aggregate_search/worker.py:216/412/508/850` 在 4 条主路径上**再各强制赋值一次 False**。所有真实调用点都在不可达分支里。**这是 fork 遗留，本产品从未启用过代理池。**
2. 🔴 **两个从未被引用的依赖被锁进了发行包** —— `cryptography`（wheel 2.9–7 MB）与 `websockets`（还写进了 `MediaCrawler.spec:59` 的 hiddenimports）。全仓零 import，且 uv.lock 里**没有任何包的 requires-dist 依赖它俩**。删除收益最大。
3. 🔴 **`worker.py:624-635` Playwright context 泄漏** —— `launch_persistent_context` 之后的三步初始化在 `try` **之外**，`finally: await context.close()` 覆盖不到。任一初始化异常就会把 `browser_data/` 的持久化 profile **锁死**，之后所有复用该 profile 的 worker 全部失败。这是唯一一个会真实伤到用户的功能性缺陷，建议**脱离重构计划单独修**。

### 6.1 负收益抽象（侦察组已论证 + 我认同）

| 不要做 | 为什么 |

| **统一四个平台 `field.py` 的同名枚举** | 名字撞车但底层类型互斥：xhs 是 `str`（`"general"`）、douyin 是 `int`（`0/1/2`）、bilibili 又是另一套 `str`。基类化只能收敛到空壳，之后每个取值都要加 `isinstance` 分支 —— 抽象反而掩盖差异 |

| **合并 4 个平台的 request helper log 脱敏** | `xhs/client.py:46-56` 的 `_safe_debug_message`、`zhihu/client.py` 的 safe_message 覆盖、`worker.py:1103-1108` 只打异常类型不打内容 —— **都是有意为之的安全措施**，别当重复样板「简化」掉 |

  `pytest -q` 不带 `--basetemp`、`:39-41` 用 `npm` —— 两条都与 `AGENTS.md` 记录的本机环境坑冲突，
  **在本机跑 `build_exe.ps1` 必然失败**（CI 的 ubuntu 环境不受影响）
