## 2. 改了什么

### 2.1 后端：登录验证必须在浏览器会话内完成（**这是本分支最重要的修复**）

真机现象：小红书扫码成功后、另外三个本来就已登录的平台，**四个全部显示「登录失败」**，
但搜索与收藏夹都正常。

根因：`aggregate_search/worker.py::_run_login` 原来把 `_verify_login_success` 放在
`crawler.start()` **返回之后**调用。而四个平台的 `core.py` 都是这个形状：

```python
async def start(self):
    async with async_playwright() as playwright:   # 退出时浏览器已关闭
        ...
        if not await self.client.pong():           # 已登录则跳过扫码
            await login_obj.begin()
        await self.search()
```

`start()` 返回时 `browser_context` 已关闭 → `ctx.cookies(urls)` / 抖音的 `pong(ctx)` 必然抛错
→ 一律判为 `login_verification_failed`。profile 其实已经写好，所以搜索/收藏夹不受影响。

改法：把验证挪进 `search()` 钩子（`_verify_then_noop_search`）—— `search()` 是各平台
`start()` 里唯一「登录流程已结束、浏览器还活着」的时刻。

- 允许重试 1 次（`_LOGIN_VERIFY_ATTEMPTS = 2`，间隔 1 秒），减少刚扫完码会话还没生效的假阴性；
- `verify_state["checked"]` 为真才用会话内结论；没走到 `search()` 时退回会话外验证，
  并给独立文案「登录流程未走到验证步骤」——不再冒充「未登录」；
- `running` 状态文案补了一句「若该平台已经是登录状态，窗口会自动关闭」。

> ⚠️ 这条别改回去。原来的测试还把它**固化**了：`tests/test_worker_login_done.py` 的
> `_FakeCrawler.start` 不调用 `search()`，`_FakeCtx.cookies()` 永不失败 —— 等于把有 bug 的
> 设计写成断言。我已给 `_FakeCtx` 加 `closed` 标志（模拟真实关闭）并补 3 条回归用例。

### 2.2 后端：不再弹多余的二维码窗口

真机反馈：可见浏览器窗口里平台登录页自己就画着二维码，`tools/crawler_util.py::show_qrcode`
又用 PIL `image.show()` 弹一个系统图片查看器，纯重复且盖住浏览器。

改法：`show_qrcode` 只在 `config.HEADLESS` 为真时弹窗（无头时没有别的办法把二维码给用户）。
必须**调用时**读 `config.HEADLESS`（`import config`，不能 `from config import HEADLESS` 取快照
—— worker 会在运行中改写它）。新增 `tests/test_qrcode_popup.py` 锁住这条。

### 2.3 前端：扫码登录成为主路径

- **新增 `webui/src/lib/scanLogin.ts`**（纯逻辑、无 React 依赖）：接口常量、`pending/running`
  vs `succeeded/failed/timed_out` 判定、状态→文案/色调视图、按钮文案、
  `scanLoginErrorMessage`（把 409 的三种来源翻译成可操作中文：搜索进行中 / 已有登录 / 其他账号操作）、
  以及**进程级「正在扫码登录」登记**（带 TTL 自愈）。
- **`webui/src/components/accounts/AccountsPage.tsx`**：
  - 每张卡片主按钮 = `btn small primary`「扫码登录」，扩展同步降为 `btn small`「从浏览器同步」并带 title 说明；
  - 修掉一个既有缺陷：旧实现用单个 `auxOpen` 布尔量，展开一个平台的登录面板会串到**所有**卡片；
    现在按平台独立（`loginOpen`），登录任务也按平台跟踪（`loginJobs`），不随折叠丢失；
  - 1.5s 轮询任务，终态时 `invalidateAccounts` + 主动 `POST /accounts/{p}/verify`，
    让卡片真正翻成「已连接」；
  - 顶部、底部 info-box、禁用按钮提示、扩展阻断文案全部改为指向扫码登录。

### 2.4 前端：扫码登录要进搜索闸门（否则搜索吃 409）

扫码登录**不写账号状态**（只有扫码成功后才验证并写），所以搜索前的账号闸门
（原本只看 `syncing`/`verifying`）看不见它 —— 用户点完扫码再搜索就会撞后端 409。

改法：`lib/accountGate.ts` 的 `waitForAccountOpsIdle` 加了可选 `extraBusy?: () => boolean`
（失败开放，与原有语义一致），`hooks/useAggregateSearch.ts` 传入 `isAnyScanLoginActive`。
离开账号页时 `clearAllScanLogins()` 清登记，避免登记比轮询活得更久。

### 2.5 前端：重启后自动复核已有登录状态

真机现象：退出重开程序后卡片显示「已导入，未确认登录」，但搜索/收藏夹正常。

这是**后端设计**：`api/services/accounts.py` 的 `_platform_state` 只在内存里，
`_state_of()` 里 profile 存在只等于 `unverified`（`connected` 必须来自真实 pong）。
装了扩展时 Round 18 的自动同步会顺带验回来；**方案 A 不装扩展就没人补这一刀**。

改法（纯前端，后端零改动）：`hooks/useAutoAccountSync.ts` 加第二条路径 —— 扩展不可用时，
对「本地有 profile 但未确认」的平台直接 `POST /api/search/accounts/{platform}/verify`。

- 新增纯函数（`lib/accountBulkSync.ts`）：`platformsNeedingVerify`（只挑 `profile_exists && !verified`）、
  `decideStartupVerify`、`shouldAnnounceStartupVerify`、`buildVerifySummaryMessage`；
- `lib/extensionSync.ts` 新增 `verifyResponseToSyncResult` / `requestPlatformVerify`：
  把 verify 响应折成 `SyncResult` 形状复用同一份 `mapSyncResultToOutcome`，
  **不新增第二套「什么算已验证」的规则**；
- 与自动同步**共用同一个冷却时间戳**（`lastAttemptRef`），扩展已连接时直接
  `skipReason="extension_connected"`，同一轮不会重复启动浏览器；
- 打扰策略与自动同步**相反**：全部确认成功是预期结果 → 保持安静；只有出问题才提示。

### 2.6 端口可配置（本 worktree 用 8090）

  **默认仍是 8080**；`base_url()`。**端口只有这一处解析，别在别处再写死。**
- `api/main.py`（`python -m api.main`）与 `desktop_main.py`（桌面/打包入口）改用它；
- `启动.bat` 第 10 行 `if not defined SIYE_PORT set "SIYE_PORT=8090"`，其余全部 `%SIYE_PORT%`；
- `scripts/start.ps1` 加 `-Port` 参数并读 `$env:SIYE_PORT`，**默认保持 8080 不变**（见 §7）；
- `webui/vite.config.ts` dev 代理、`scripts/search_metrics_probe.py`、
  `scripts/auto_account_sync_smoke.py` 都跟随同一套规则。

> ⚠️ 编码坑：`启动.bat` 是 **GBK**、`scripts/start.ps1` 是 **UTF-8 带 BOM**。
> 改这两个文件必须用 Python 按原编码读写；用普通编辑器/补丁工具写成 UTF-8 会把中文提示变乱码
> （`start.ps1` 若丢 BOM，PowerShell 5.1 会把中文读成 ANSI）。

## 3. 不要改回去的 6 条不变量

1. **登录验证必须在 `crawler.start()` 内部**（现为 `search()` 钩子）—— 会话外验证必然失败（§2.1）。
2. **不要把 `verified` 持久化到磁盘**：`connected ⇒ 真实验证` 是刻意的安全不变量；
   重启后的「未确认」由前端自动复核补偿，而不是靠信任一个旧标记（§2.5）。
3. **`show_qrcode` 只在 `HEADLESS` 时弹窗**，且必须调用时读 `config.HEADLESS`（§2.2）。
4. **端口只在 `base/server_port.py` 解析一处**，产品默认 8080（§2.6）。
5. **扫码登录成功前不得声称成功**：只有后端在会话内验证通过才发 `succeeded`（§2.1）。
6. **`AccountAutoSync` 只挂在应用根部**，账号页不自己跑队列；两条路径共用冷却时间戳（§2.4/2.5）。

## 8. 合并后的真机冒烟清单

1. 起服务 → 打开「设置 · 账号与登录」：卡片主按钮应是「扫码登录」，扩展同步是「从浏览器同步」。
2. 点任一新平台「扫码登录」：会打开可见浏览器窗口，**不应**再弹独立的二维码图片窗口；
   用手机扫码 → 卡片应显示「登录成功，会话已验证并保存」并变「已连接」。
3. 点一个**已经登录**的平台：窗口会闪一下自动关闭 → 这次应该报**成功**（修复前必报失败）。
4. 完全退出程序再打开：卡片先显示「已导入，未确认登录」，几秒后自动变回「已连接」，
   **不应**弹任何 toast。
5. 扫码登录进行中立刻发起搜索：应等登录结束再提交，不该出现 409 报错。
6. 搜索、收藏夹、跨平台收藏各跑一次。
