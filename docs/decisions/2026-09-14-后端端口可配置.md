# 后端端口可配置（`SIYE_PORT`）

- **日期**：2026-09-14
- **状态**：已实施（产品默认值未变，仍是 8080）
- **相关**：`docs/features/tray-launcher.md`、`docs/features/extension-login.md`、`AGENTS.md`

## 背景

同一个仓库可以存在多个 check-out（git worktree），两个人/两个 agent 各跑一份。
两份都抢 `127.0.0.1:8080` 时第二个起不来；而端口在代码里是散落的字面量
（`api/main.py`、`desktop_main.py`、`tray_main.py`、`scripts/start.ps1`、vite dev 代理各写一份），
改一个漏一个。

## 选项

**A. 把默认端口改成别的（例如 8090）**
- 优点：改一处即可。
- 缺点：**浏览器扩展的 host 权限、manifest、文档、发布流程全部绑在 8080**，
  改默认值等于同时改一堆地方，且老用户升级后会"打不开"。

**B. 保持 8080 为产品默认，另加环境变量覆盖 —— 只有并行开发时显式设置**
- 优点：产品行为零变化，扩展不用动，文档不用改；并行场景自己设变量即可。
- 缺点：端口解析必须在**唯一一处**实现，否则又会散掉。

## 决定

选 **B**。`base/server_port.py` 是端口解析的唯一来源：

- `resolve_port()`：`SIYE_PORT`（合法时）→ 默认 8080；非数字/空值/越界**静默回退**（启动阶段不该因为环境变量打错就崩）。
- `base_url()`：拼本机页面地址。
- `api/main.py`、`desktop_main.py`、`tray_main.py`、`scripts/start.ps1 -Port`、
  `webui/vite.config.ts` 的 dev 代理都读它。
- 支线任务 worktree 的 `启动-源码.bat` 把 `SIYE_PORT` 默认设成 **8090**，
  这样双击就能和主目录的 8080 并存。

## 后果 / 待办

- 产品默认端口仍是 **8080**，扩展（`browser_extension/` 的 `API_ORIGIN` 与 manifest host 权限）
  **只认 8080**：在换端口的实例上请用内置扫码登录，不要用扩展同步。
  `tests/test_extension_security.py` 断言了这一点，改扩展要同步改测试与文档。
- 新增任何"自己监听/自己访问自己的"入口时，必须走 `resolve_port()`，
  不要再写端口字面量。
- 本决策此前缺失（交接文档 `交接-feat-scan-login.md` 里点名要补），2026-09-14 补上。
- 相关测试：`tests/test_server_port.py`（9 条）。
