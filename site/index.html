Why

四个平台 × 四次搜索，本来就是一件事

找一个答案的过程被平台切成了四份：每个站的检索、排序、互动口径都不一样，你只能靠记忆和来回切换把它们拼起来。四野只改一件事——把这一步合成一次。

现在（没有它）

四个平台 × 四次搜索

  • 依次打开小红书、抖音、B站、知乎
  • 同一个关键词，手动输入四遍
  • 四套排序规则，靠记忆横向对比
  • 同一条内容在多个平台重复出现，得自己认出来
  • 找到有用的结果，还得手动复制链接记下来

Features

搜索只是入口，能用起来的部分在后面

不是把四个网页塞进一个 iframe。后端把各平台结果归一化成同一套结构，再统一做排序、去重、补全和缓存。

四平台并行搜索

四个平台同时发起，支持部分结果返回。单个平台失败、超时或被取消时，其他平台的结果照常展示，并可对失败平台单独重试。

受控的 Provider fallback：轻量接口走不通时按已有路径回退。

统一结果模型

标题、摘要、作者、发布时间、封面与互动数据统一成同一种结构，跨平台也能按同一套字段阅读和对比。

互动数据按「播放 / 点赞 / 投币 / 评论 / 收藏 / 分享」固定顺序陈列，有值才显示。

三种排序

「综合」合并关键词相关性、新鲜度、互动表现与平台多样性；「最新」按时间；「互动最多」让评论、收藏等深度互动权重大于播放量。

结果内筛选与高亮

近 7 天 / 近 30 天、内容类型、关键词组合筛选；多个关键词分别匹配标题、作者和摘要，标题与摘要里的关键词会高亮。

筛选只处理已经返回的内容，不会额外搜索平台。

跨平台去重与分组

同一条内容出现在多个平台时合并展示，同时保留每个平台的入口，可以逐个收藏或取消。

规则判断：标题相同或近似还需作者或有效摘要佐证，不靠同名硬合并。

本地收藏与备注

收藏保留当时的内容快照和原文链接，可写备注，刷新页面或重启程序后仍在。最多 500 个来源，每条备注 1000 字。

存在当前浏览器的本地存储里；支持导出 / 导入 JSON 备份（≤ 10 MB），全程本地完成。

跨平台收藏

只读拉取已登录账号在小红书、抖音、B站、知乎的收藏，在一个页面统一筛选、导出，或保存到本地收藏。

只发读取请求，不会在平台侧新增、删除或移动收藏。

导出与批量复制

未勾选时导出当前筛选下的全部结果，勾选后只导出选中的条目；CSV 带 UTF-8 BOM，Excel 打开中文不乱码，Markdown 适合整理笔记，也可以批量复制原文链接。

搜索前登录预检

启动浏览器前先做一次完全本地的登录预检（实测约 1 毫秒）：确定搜不了的平台立刻提示「需要登录」并指向账号设置，不再白等十几秒。

cookie 库读不出来时一律放行，绝不因为读不出文件就把搜索拦掉。

更多底层能力：摘要补全与缓存、搜索统计与限流、账号诊断

摘要补全与缓存

先用 snippet 摘要，缺少有效摘要的前排结果由后台补全，不阻塞首屏。90 秒短期内存结果缓存，可强制重新搜索。

搜索统计与限流冷却

最近 100 次搜索的耗时、平台成功率、缓存命中率、备用路径使用率和失败原因一目了然，也可直接读接口做对比。

平台明确限流后进入 60 秒冷却，重复触发依次延长为 120 / 240 / 300 秒封顶；其他平台继续搜。

账号状态与平台诊断

打开程序即自动检测账号状态，为未确认登录的平台自动同步；平台诊断会分别展示账号状态、当前搜索路径和 fallback 能力。

账号状态不等同于搜索能力，没登录也可能完成公开搜索。

Download

三步就能搜起来

Windows 可执行包已经包含 Python runtime、FastAPI 后端和生产版 Web UI。普通使用不需要安装 Python、uv、Node.js、npm。

1

下载并解压

下载 MediaCrawler-Windows-x64.zip，解压到一个有写入权限的目录。不要只复制其中的 EXE。

2

双击启动

打开解压出的 MediaCrawler 文件夹，双击 MediaCrawler.exe，等控制台出现 backend ready。

3

开始搜索

程序会自动打开系统默认浏览器（127.0.0.1:8080），输入关键词、选平台，回车。

下载 Windows x64 安装包

发布包由 GitHub Actions 在 Windows 上真实构建，并在 clean-room 中解压验证后才上传；同时提供 .sha256 校验文件。

前往 Releases 下载 查看源码

如果 Releases 里暂时还没有可下载的包：在仓库的 Actions 页面手动运行 Windows Executable Release 工作流即可生成安装包，或直接按下面的「从源码运行」在本机跑起来。

  • 系统：Windows 10 / 11 x64
  • 浏览器：系统 Chrome 或 Edge（Windows 通常自带 Edge）
  • 其他依赖：无。Python、Node.js 都打包在包里
  • 端口：默认 127.0.0.1:8080，只监听本机
  • 隐私：账号 profile、缓存和运行数据都存在本机目录，不上传

运行期间不要删除 EXE 旁边的 _internal、webui 等运行文件。如果 /api/health 显示浏览器不可用，先装好或修复 Chrome / Edge 再重启。

可选：同步账号登录状态

公开搜索不一定要求四个平台都登录。只有需要登录态、详情接口或更稳定的平台访问时，才需要同步账号。

  1. 在 Chrome / Edge 打开 chrome://extensions 或 edge://extensions
  2. 打开「开发者模式」，选择「加载已解压的扩展程序」
  3. 选择解压目录里的 MediaCrawler/browser_extension/
  4. 在浏览器里登录平台，回到「账号与登录」点同步登录状态

扩展只把必要的会话信息同步给本机后端，请只同步和使用你有权使用的账号。

程序打开时会自动检测账号状态，并为尚未确认登录的平台自动同步一次；平台诊断会分别展示账号状态、当前搜索路径与 fallback 能力。

账号状态和搜索能力是两件事：账号还没通过 API 验证时，平台仍可能通过浏览器备用路径完成公开搜索。 搜索与账号同步互斥，切换时不会互相打断。

For Developers

从源码运行

需要 Python 3.11+、uv、Chrome/Edge 或 Playwright Chromium；Node.js 20 只在开发和构建前端时需要。

1. 拉取并安装后端依赖 Web UI 与 EXE 用同一个地址

git clone https://github.com/KellenGO/MediaCrawler.git
cd MediaCrawler
uv sync

# 用项目管理的 Chromium 时，首次执行一次
uv run playwright install chromium

2. 构建前端 生成 webui/dist

cd webui
npm ci
npm run build

3. 启动后端

uv run uvicorn api.main:app \
  --host 127.0.0.1 --port 8080 --reload

一键启动（Windows）

# 仓库根目录双击，或命令行执行
MediaCrawler.bat

前端开发模式

cd webui
npm run dev   # http://localhost:5173，/api 代理到 8080

FAQ

你大概会问的几个问题

用之前必须先登录四个平台吗？

不一定。公开搜索不要求四个平台都登录。只有需要登录态、详情接口或更稳定的平台访问时才需要同步账号。

没登录时，搜索前的本地预检会在毫秒级告诉你是哪个平台搜不了、为什么，并把你引到账号设置，而不是让你白等浏览器启动。

我的账号和数据会被上传到服务器吗？

不会。后端只监听 127.0.0.1:8080，搜索请求由本机发出；账号 profile、缓存和运行数据都在本机目录里。

本地收藏和备注存在当前浏览器的本地存储中，导出 / 导入 JSON 备份也完全在浏览器本地完成，不上传任何内容。

搜索结果里显示「缓存」是什么意思？

后端对搜索结果做 90 秒的短期内存缓存，同一关键词在 90 秒内重复查看会直接回放缓存，平台状态里会显示原采集时间。

点「重新搜索」可以强制拿到最新结果；重复查看和后台摘要补全不会延长缓存有效期。缓存成功才更新，失败时会保留尚未过期的旧缓存。

某个平台搜不出结果 / 结果不完整怎么办？

先看平台状态：需要登录就按提示去账号设置同步；明确被限流会显示冷却倒计时，冷却期间重复搜索不会向该平台发新请求，也不会延长倒计时。

单个平台失败不会影响其他平台返回结果，可以对失败平台单独重试。冷却结束后的重试需要手动点。

为什么有些结果的互动数据不完整？

各平台搜索接口提供的字段本来就不一样：小红书和抖音的搜索接口不返回播放量，B站的投币数只在视频详情里，知乎搜索结果不返回收藏数。

缺失的指标不会占位，也不会为了凑数字额外逐条抓详情。这是已知限制，不是显示错误。

能在 Mac 或 Linux 上用吗？

目前只提供 Windows x64 可执行包。其他系统可以从源码运行：项目的后端和前端都是跨平台的，按「从源码运行」的步骤准备 Python 3.11+、uv 和 Chrome/Edge 即可。

启动时提示 8080 端口被占用 / 缺少 webui/dist？

端口被占用时，先关掉占用该端口的本项目实例；程序不会强制终止其他应用，也不会自动改端口。

从源码启动提示缺少 webui/dist 时，先进入 webui 执行 npm ci 和 npm run build 生成生产前端。
