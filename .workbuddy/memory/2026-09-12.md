## 环境备注

- 本机 bash（Git Bash shim）不可用（`ls`/`dirname` 缺失），Bash 工具执行会 127。用 PowerShell 工具；且 PowerShell 的 stdout 不回显，需把结果 `Out-File` 到临时文件再用 Read 读取。

## 跨平台收藏夹：修复四平台拉取 + 免手动同步

### 问题 1：小红书 / 抖音收藏夹报错

三个叠加原因：

1. **浏览器解析器缺失**。`media_platform/xhs/core.py` 和 `media_platform/douyin/core.py` 的 `launch_browser` 直接用 Playwright 自带 chromium，没有调用 `resolve_playwright_browser()`（知乎、B站 都调用了）。本机自带 chromium 版本不匹配 → `Executable doesn't exist at ...chromium_headless_shell-1228`。修复：两个文件都按 bilibili/zhihu 的模式接入解析器，并在 `backend == "playwright-chromium"` 时校验可执行文件存在。
2. **小红书收藏接口下线**。`/api/sns/web/v1/note/collect/page` 现在返回 `404 page not found`（HTML 响应体 → `JSONDecodeError: Extra data: line 1 column 5`）。改为 `/api/sns/web/v2/note/collect/page`。
3. **v2 必须带 `user_id`**，否则返回 `-9109 参数错误`；同时响应列表字段从 `items` 变成 `notes`。`user_id` 既不在 cookie 里也拿不到 `/api/sns/web/v2/user/me`（该接口对我们的客户端回 406），最终从已加载页面的 `window.__INITIAL_STATE__.user.userInfo.value.userId` 读取（新增模块级 `_resolve_self_user_id(context_page)`，并有 DOM `/user/profile/<id>` 链接兜底）。注意必须在 `start()` 内部调用——`start()` 返回后 playwright 上下文已关闭。

另外补了 XHS adapter 的两处数据质量：收藏列表封面在 `cover.info_list[].url`（原来只认 `cover.url_default/url_pre/url`）；互动数是 `"10万"` 这类中文单位，新增 `_parse_count` 支持 万/亿/w。

### 问题 2：每次进页面都要手动同步

原因：结果只存在前端 `useFavorites` 的 `jobId` state 里，导航离开即丢失；后端 `FavoritesJobManager._recent` 其实一直留着快照但没暴露。

修复：
- 后端新增 `FavoritesJobManager.latest()` + `GET /api/search/favorites/jobs/latest`（必须声明在 `/favorites/jobs/{job_id}` **之前**，否则 `latest` 会被当成 job_id）。
- 前端 `useFavorites` 进入时先取 latest 直接渲染，**不做任何自动同步**——用户明确要求"保留上次结果，而不是自动重新同步"。只有点击"同步收藏夹 / 重新同步"才会读平台；只在离开页面时任务仍在 running 的情况下把该 job_id 接过来继续轮询（不发起新请求）。

**关键坑（不要再踩）**：`App.tsx` 的 `viewMode` 是条件渲染，切走会**卸载** `FavoritesPage`，组件 state 全丢，只有 React Query 的缓存存活。所以 `["favorites-latest"]` 这个 query **不能设 `staleTime: Infinity`**——首次进入时缓存的是 404→null，之后每次挂载都会直接命中缓存不再请求，快照就永远显示不出来。保持默认 staleTime（0），让每次挂载都重新读一次本地接口。

## 收藏夹页面的四个 bug（用户二次反馈）

注意：用户这次说的是**跨平台收藏页**，不是搜索结果。上一轮的修复不影响这里——收藏走的是各平台的收藏列表接口，字段比搜索更少。实测各平台收藏列表的真实形状：

- **小红书** collect/page：`interact_info` 只有 `{liked, liked_count}`。且大数写作 `"10万+"`（带 `+`）。
- **抖音** listcollection：`statistics` 有 digg/collect/comment/share，`play_count` 为 0；**额外带 `share_url`**。
- **B站** `/x/v3/fav/resource/list`：`medias[].cnt_info = {play, danmaku, collect, reply:0, ...}`，**收藏数叫 `collect` 不是 `favorite`**，且没有 like/coin。
- **知乎** collections/{id}/items：`data[].content` 只有 `voteup_count` / `comment_count` / `thanks_count`，**完全没有 `visits_count` / `favorites_count`**。

### 修复

1. **抖音链接点不开**：适配器优先用 `share_url`，它指向 `www.iesdouyin.com`，不在前端 `safeContentUrl` 白名单（`douyin.com` 等）内 → 返回 null → 卡片不渲染成 `<a>`。且 share_url 带 `u_code` / `share_sign` 跟踪参数。改为**始终**用 `https://www.douyin.com/video/{aweme_id}`。
2. **B站看不到收藏数**：`_extract_metrics` 的 stat 映射只认详情接口的 `favorite`，补上收藏夹列表的 `collect`。
3. **小红书只有点赞数**：`_parse_count` 没处理 `"10万+"` 末尾的 `+`，导致这类条目**一个指标都不显示**。加 `rstrip("+")`。
4. **弹幕没必要**：从 `METRIC_ORDER` 移除 `danmaku_count`（后端仍采集），同时清理 ResultCard 里对应的 `Tv` 图标与 import。

### 验证

- 后端 786 passed / 前端 230 passed / build 通过。
- 真实收藏夹复验：小红书 `{"like_count": 100000}`（原来这条是 `{}`）、抖音 4 项指标 + 链接变成 `www.douyin.com/video/...`、知乎 2 项。
- 真实浏览器复验：10 个平台链接全部为合法域名、无 `iesdouyin`/`u_code`；抖音卡片按“点赞/评论/收藏/分享”顺序显示。

## 互动数据图标替换（纯前端）

用户指定：点赞=大拇指、评论=消息气泡、投币=B站投币图标、浏览=眼睛、收藏=星星。

原来的映射是 点赞=心形、收藏=大拇指、投币=lucide Coins，都不符合，已全部改掉。

**B站投币图标的取得方式**（lucide 里没有等价形状，不要拿 Coins 凑数）：B站视频页工具栏的投币按钮是**内联 SVG**（`svg.video-coin-icon`，viewBox 0 0 28 28，单 path + `fill-rule="evenodd"` + `fill="currentColor"`）。用 Playwright 打开 B站视频页，`document.querySelector('svg.video-coin-icon').outerHTML` 就能拿到完整路径。已存为 `webui/src/components/icons/BilibiliCoinIcon.tsx`。

**形状确认**：对 B站播放页工具栏截图看到 点赞=实心大拇指、**投币=实心圆 + ¥ 镂空**、**收藏=星星**、分享=箭头——即 B站 原生就用星星表示收藏，和用户要求一致，图标选择是对的。

`METRIC_ICONS` 的类型从 `Record<string, typeof Eye>` 改成 `Record<string, ComponentType<{className?: string}>>`，否则自定义组件无法和 lucide 图标共存。同时清理了不再使用的 `Heart` / `Coins` / `Tv` import。

- 真实浏览器截图收藏页卡片：抖音那行渲染为 大拇指 3.4k / 气泡 29 / 星星 5.4k / 分享 519，4 个 SVG 全部就位。
