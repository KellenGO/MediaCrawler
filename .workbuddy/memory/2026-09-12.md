## 环境备注

- 本机 bash（Git Bash shim）不可用（`ls`/`dirname` 缺失），Bash 工具执行会 127。用 PowerShell 工具；且 PowerShell 的 stdout 不回显，需把结果 `Out-File` 到临时文件再用 Read 读取。
- `pytest` 默认 `tmp_path` 夹具会因 `C:\Users\Kellen\AppData\Local\Temp\pytest-of-Kellen` 权限被拒（WinError 5）而报 33 个 setup error。必须加 `--basetemp=<仓库内目录>`，否则会误判为回归失败。

## 跨平台收藏夹：修复四平台拉取 + 免手动同步

### 问题 1：小红书 / 抖音收藏夹报错

三个叠加原因：

1. **浏览器解析器缺失**。`media_platform/xhs/core.py` 和 `media_platform/douyin/core.py` 的 `launch_browser` 直接用 Playwright 自带 chromium，没有调用 `resolve_playwright_browser()`（知乎、B站 都调用了）。本机自带 chromium 版本不匹配 → `Executable doesn't exist at ...chromium_headless_shell-1228`。修复：两个文件都按 bilibili/zhihu 的模式接入解析器，并在 `backend == "playwright-chromium"` 时校验可执行文件存在。
2. **小红书收藏接口下线**。`/api/sns/web/v1/note/collect/page` 现在返回 `404 page not found`（HTML 响应体 → `JSONDecodeError: Extra data: line 1 column 5`）。改为 `/api/sns/web/v2/note/collect/page`。
3. **v2 必须带 `user_id`**，否则返回 `-9109 参数错误`；同时响应列表字段从 `items` 变成 `notes`。`user_id` 既不在 cookie 里也拿不到 `/api/sns/web/v2/user/me`（该接口对我们的客户端回 406），最终从已加载页面的 `window.__INITIAL_STATE__.user.userInfo.value.userId` 读取（新增模块级 `_resolve_self_user_id(context_page)`，并有 DOM `/user/profile/<id>` 链接兜底）。注意必须在 `start()` 内部调用——`start()` 返回后 playwright 上下文已关闭。

另外补了 XHS adapter 的两处数据质量：收藏列表封面在 `cover.info_list[].url`（原来只认 `cover.url_default/url_pre/url`）；互动数是 `"10万"` 这类中文单位，新增 `_parse_count` 支持 万/亿/w。

### 问题 2：每次进页面都要手动同步

原因：结果只存在前端 `useFavorites` 的 `jobId` state 里，导航离开即丢失；后端 `FavoritesJobManager._recent` 其实一直留着快照但没暴露。

修复：
- 后端新增 `FavoritesJobManager.latest()` + `GET /api/search/favorites/jobs/latest`（必须声明在 `/favorites/jobs/{job_id}` **之前**，否则 `latest` 会被当成 job_id）。
- 前端 `useFavorites` 进入时先取 latest 直接渲染，**不做任何自动同步**——用户明确要求"保留上次结果，而不是自动重新同步"。只有点击"同步收藏夹 / 重新同步"才会读平台；只在离开页面时任务仍在 running 的情况下把该 job_id 接过来继续轮询（不发起新请求）。

**关键坑（不要再踩）**：`App.tsx` 的 `viewMode` 是条件渲染，切走会**卸载** `FavoritesPage`，组件 state 全丢，只有 React Query 的缓存存活。所以 `["favorites-latest"]` 这个 query **不能设 `staleTime: Infinity`**——首次进入时缓存的是 404→null，之后每次挂载都会直接命中缓存不再请求，快照就永远显示不出来。保持默认 staleTime（0），让每次挂载都重新读一次本地接口。
